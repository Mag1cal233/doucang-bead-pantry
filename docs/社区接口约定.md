# 一粒画社区接口约定

这份约定用于把当前前端社区切换为真实的跨设备作品流。前端只依赖登录会话和公开昵称；账号准入由上游账号系统处理，社区接口不接收或返回额外身份资料。

## 启用方式

构建前设置：

```text
NEXT_PUBLIC_COMMUNITY_API_BASE=https://api.example.com
```

未设置时，页面会明确显示“本机社区预览”，数据只保存在当前浏览器。设置后，前端使用浏览器会话 Cookie 请求以下接口。

## 作品结构

```ts
type CommunityPost = {
  id: string;
  projectId?: string;
  title: string;
  description: string;
  category: "动物" | "卡通" | "人物" | "植物" | "食物" | "风景" | "文字" | "其他";
  authorNickname: string;
  publishedAt: number;
  size: number;
  beadCount: number;
  colorCount: number;
  preview: string[];
  palette: string[];
  likeCount: number;
  favoriteCount: number;
  likedByViewer: boolean;
  favoritedByViewer: boolean;
  ownedByViewer: boolean;
};
```

`preview` 只包含图纸格子的 `#rrggbb` 或 `transparent`，最多 13,456 格；`palette` 最多 264 色。接口不应接收或保存用户上传的原始图片。

## 接口

### 获取作品流

`GET /v1/community/posts`

```json
{ "posts": [] }
```

互动状态和 `ownedByViewer` 必须按当前会话计算，计数由服务端返回，不能相信客户端提交值。

### 发布作品

`POST /v1/community/posts`

请求体只包含 `projectId`、`title`、`description`、`category`、`size`、`beadCount`、`colorCount`、`preview` 和 `palette`。响应体为完整 `CommunityPost`。

### 点赞或收藏

`PUT /v1/community/posts/:id/reactions/:reaction`

`reaction` 只能是 `like` 或 `favorite`。

```json
{ "active": true }
```

成功响应：

```json
{ "ok": true }
```

写入应使用“用户 + 作品 + 互动类型”唯一约束，重复请求保持幂等。

### 撤下作品

`DELETE /v1/community/posts/:id`

仅作品作者或社区管理角色可执行。成功响应：

```json
{ "ok": true }
```

## 服务端最低要求

- 只允许可信站点来源跨域访问，并设置 `Access-Control-Allow-Credentials: true`。
- 会话 Cookie 使用 `HttpOnly`、`Secure` 和合适的 `SameSite` 策略；跨站部署时增加 CSRF 防护。
- 校验标题、说明、分类、画布尺寸、色值格式和数组长度，不直接信任客户端计数或作者信息。
- 发布、互动和删除分别限流；记录可追溯的审核日志，但不把内部账号资料返回给作品流。
- 未登录请求读取作品流可以按内测策略开放；发布、互动和删除必须返回 `401` 或 `403`，不要伪造成功。
- 通用错误响应使用 `{ "error": "稳定错误码" }`，避免把堆栈和数据库信息发给浏览器。
